# Landos — Design Document Changelog

Version history for `spec/design/landos-design-vX.X.X.md`. Maintained separately from the design doc itself to keep that document focused on the current design.

| Version | Date | Changes |
|---|---|---|
| v0.1.0 | 2026-05-17 | Initial draft (as Fundos) |
| v0.1.1 | 2026-05-18 | Token model expanded to 3D (X, Y, Z); two-tier supply model introduced |
| v0.1.2 | 2026-05-18 | Name changed to Landos (LAND OS); ownership validation mechanisms expanded; identity verification added |
| v0.1.3 | 2026-05-18 | Token ticker LOS confirmed; ownership status system; transfers and succession; Community Hubs; Tendermint BFT confirmed |
| v0.1.4 | 2026-05-29 | Token model redesigned: two instruments (Land Record NFT + LOS fungible token); De Soto dead capital framework added as philosophical pillar; node economics section added (tiered nodes, LOS rewards); prior art / failed projects analysis added; government relationship clarified (legitimacy earned through adoption, not permission); open questions updated |
| v0.1.5 | 2026-05-30 | Landos Foundation added (Section 5): minimal operational entity, support operations, LOS worker compensation, no protocol control; key recovery system added (Section 16): tiered recovery paths, recovery portal, 3 recovery contacts at registration, 72-hour time-lock, AI-assisted automation, LOS-rewarded human escalation; node model finalized: relay nodes added, geographic nodes removed; sections renumbered throughout; What Landos Is Not updated to reflect Foundation and 4.3 framing |
| v0.1.5 | 2026-06-01 | Asset model clarified: Parcel Record introduced as foundational protocol primitive (Section 6.2); token model updated from two instruments to three layers (Parcel Record → Land Record NFT → LOS); parcel lifecycle defined (subdivision, consolidation, boundary adjustment, contested boundary); section 6 renumbered throughout. Griefing defense added (Section 12): Land Witness, Interested Party Exclusion, Personal Validation Score (PVS), Hold Period, Dispute Bond; all sections renumbered. Staged entry model added (Section 13.1): four stages × 7 days minimum = 28 days to Confirmed; confirmation depth introduced (Section 13.2) |
| v0.1.6 | 2026-06-07 | ZK design session complete (Section 19.0): ZK Location Proof (point-in-polygon circuit, 10m edge tolerance, chain sees valid/invalid only); ZK Identity Proof (Persona VC private, chain sees verified-unique-human only, multi-provider support); ZK Attestation Proof (neighbor quorum signatures private, chain sees valid/invalid + nullifier hashes, cross-parcel privacy via parcel-specific nullifiers); ZK Score Proof (threshold range proof, chain sees pass/fail vs. confirmation floor only, selective disclosure to Land Witness for disputes). Bootstrapping model: creator runs first nodes (Bitcoin model), soft threshold for open registrations (exact validator count TBD at testnet). All implemented via gnark (Go-native, Cosmos SDK compatible). Previous: Dispute Bond finalized (Section 12.5): bond in escrow, scales with PVS + confirmation depth, Hub subsidy covers legitimate claimants. Hub activation threshold (Section 15.1): adaptive by density, exact values TBD at testnet. Proof of Habitation anti-gaming (Section 11.1): liveness challenges, cross-signal anomaly detection, community corroboration. AR Boundary Walking anti-gaming (Section 11.3): sensor fusion, video liveness, temporal cross-check, community spot-check. Node reward principles locked (Section 7.3): fixed hierarchy, validation > uptime, Bitcoin halving curve, written into genesis. Foundation jurisdiction: no incorporation before genesis. Fractional ownership (Section 6.3): NFT stays whole, co-owners in metadata, M-of-N signatures required. Key recovery penalties (Section 17.7): scaled by information advantage, support workers held to higher standard. Worst-case key recovery: no last-resort path in v1, deferred to v2. Proof of Land scoring model added (Section 10.4): habitation = time-weighted accumulation with decay floor; hub standing = contribution-weighted, outcome-adjusted, velocity-flagged; attestations = PVS-weighted, diversity-required, no decay; confirmation requires all three floors met plus combined threshold. Neighbor Quorum: 2-of-3 universal, diversity rule enforced. Hub boundary definition (Section 15.2): organic clustering, no political boundaries. Three pillars added (Section 2): People First, de Soto, Bitcoin. Onboarding philosophy added (Section 20). Node data privacy added (Section 19.0): location hashed with user-derived salt; DID role separation; social graph never on-chain; habitation aggregate score only with randomized submission; all full ZK solutions deferred |
| v0.1.7 | 2026-06-14 | LADM Alignment added (Section 21): mapped Landos's core classes to the Land Administration Domain Model (ISO 19152) — Parcel Record ↔ LA_SpatialUnit, Land Record NFT ↔ LA_BAUnit + LA_Right, landowner/validator/governance DIDs ↔ LA_Party/LA_GroupParty (community wallets and M-of-N co-ownership map to LA_GroupParty). Confirmed that the 2026-06-05 fractional ownership decision (NFT stays whole, co-owners in metadata, M-of-N signatures) is a direct instance of an LADM RRR share attribute — independent validation, not a new requirement. Identified LA_Restriction and LA_Responsibility as new standardized categories for liens, easements, conservation restrictions, and tax/fee obligations, filling the "additional tokens" gap referenced in Section 6.6. Noted LADM Edition II Part 5 (2025) 3D spatial unit support as a reference point for the deferred Z-axis/hectare-meter design question. Alignment is conceptual/translational only — no schema or implementation dependency adopted. Open Questions and Related Documents updated accordingly |
| v0.1.8 | 2026-06-14 | Pillar 1 (Section 2) extended with an explicit individual-human, gender-neutral identity principle: every person gets their own DID, co-ownership (Section 6.3) is a list of named individuals, no protocol concept of "head of household." Section 21 retitled "Land Administration Standards Alignment" and expanded with three new alignments: STDM (Section 21.7) — Social Tenure Relationship (STR) generalizes LA_Right and reframes the Section 13 status spectrum as STRs at different evidentiary stages, validating Contested status and evidence-based attestations against existing griefing-defense and validation mechanisms, with a cross-reference to the Bitland Ghana pilot (Section 22); Fit-For-Purpose (Section 21.8) — cross-checked all five FFP principles against existing Landos decisions, no gaps found, framed Landos as a decentralized permissionless FFP implementation; VGGT (Section 21.9) — mapped legitimate-tenure, anti-eviction, and access-to-justice principles to existing sections, and tied VGGT's gender-sensitive tenure governance principle directly to the new Pillar 1 statement. Added Section 21.10 (combined scope note for all four standards alignments). Open Questions and Changelog moved out of the main design doc into `community/OPEN-QUESTIONS.md` and `community/CHANGELOG.md`, with the design doc's appendix sections replaced by short pointers; Related Documents updated accordingly |
| v0.1.9 | 2026-06-14 | Registration decoupled from the social graph. New Section 11.6 ("Validation Without a Social Graph") establishes the Independent Claimant Path: registration has zero prerequisites, a claim can enter the status spectrum at Claimed with no attestations, and the five validation mechanisms (Section 11) are reframed as a menu rather than a checklist. When Neighbor Quorum can't be formed, two independent Land Witnesses plus an extended Habitation minimum substitute for it (Section 13.1 Stage 2/3/4 fallback notes). Section 20.1 onboarding now offers this as a parallel "second door" alongside "do you know your neighbor?" — a person who answers "no" is routed to Habitation tracking and Land Witness review instead of being stuck. The Notice Period remains hub-visible regardless of path, so this isn't a loophole: a real neighbor can still raise a Contest. This also resolves the open item on reviewing onboarding for gender-sensitivity in practice, since the social graph is no longer load-bearing for registration. Open Questions and Related Documents updated accordingly |
